# LPPO V5.1 Migration Guide

**Complete guide for upgrading to LPPO V5.1**

## Overview

This guide helps you migrate from any previous version of LPPO to V5.1. V5.1 is **100% backward compatible**, so your existing code will continue to work. This guide shows you how to take advantage of V5.1's 660+ new features.

## Quick Migration Checklist

- [ ] Update `Cargo.toml` version to `5.1.0`
- [ ] Rebuild project with `cargo build --release`
- [ ] Run existing tests to verify compatibility
- [ ] Review new features relevant to your project
- [ ] Gradually adopt V5.1 features
- [ ] Update documentation to reference V5.1
- [ ] Remove references to deprecated V4.0 and earlier docs

## Version-Specific Migration Paths

### From V5.0 to V5.1

**Difficulty:** ⭐ Easy
**Breaking Changes:** None
**Time Estimate:** 1-2 hours (mostly learning new features)

V5.1 is a pure feature addition on top of V5.0. Your code works as-is.

#### What You Get
- 660+ new features available
- Enhanced standard library
- Better tooling
- Improved performance (no code changes needed)

#### Recommended Actions

1. **Update version number**
```toml
# Cargo.toml
[package]
version = "5.1.0"
```

2. **Rebuild**
```bash
cargo clean
cargo build --release
```

3. **Start using new features gradually**

### From V4.0 to V5.1

**Difficulty:** ⭐⭐ Moderate
**Breaking Changes:** None (but syntax updates recommended)
**Time Estimate:** 4-8 hours

V4.0 code works in V5.1, but you'll want to modernize the syntax.

#### Migration Strategy

1. **Replace ultra-verbose keywords with readable ones**

```lppo
// V4.0 style (old, but still works)
PUBEXP PROCDEF calculate(x: I64, y: I64) -> I64 {
    BEGINSEG calc_body
    DECLVAR OWNR result: I64 = x + y;
    RETVAL result;
    ENDSEG calc_body
}

// V5.1 style (recommended)
pub proc calculate(x: Int64, y: Int64) -> Int64 {
    let own result: Int64 = x + y;
    return result;
}
```

2. **Remove mandatory annotations**

```lppo
// V4.0 style (unnecessarily verbose)
BEGINSEG main_body
MEMALIGN 64
TYPECHK enabled
DECLVAR OWNR MEMALIGN 8 x: I64 = 42;
TYPECHK x: I64;
ENDSEG main_body

// V5.1 style (clean)
let own x: Int64 = 42;
```

3. **Use new V5.1 features**

```lppo
// Add modern features like collections
use std::collections::Vec;

pub proc main() -> Void {
    let own numbers: Vec<Int64> = vec![1, 2, 3, 4, 5];
    numbers.iter().for_each(|x| out x);
}
```

### From V3.0 to V5.1

**Difficulty:** ⭐⭐ Moderate
**Breaking Changes:** None (but syntax modernization needed)
**Time Estimate:** 4-8 hours

V3.0's cryptic syntax works in V5.1, but you should modernize.

#### Migration Strategy

1. **Replace cryptic keywords**

```lppo
// V3.0 style (cryptic, but still works)
PROCDEF main() -> VOID0 {
    DECLVAR OWNR msg: STRPTR = "Hello";
    EMIT msg;
}

// V5.1 style (readable)
proc main() -> Void {
    let own msg: Str = "Hello";
    out msg;
}
```

2. **Replace cryptic type names**

| V3.0 | V5.1 |
|------|------|
| `I64` | `Int64` |
| `BOOL8` | `Bool` |
| `STRPTR` | `Str` |
| `VOID0` | `Void` |
| `ARRPTR` | `Arr<T>` |

3. **Adopt V5.1 features**

### From V2.0 to V5.1

**Difficulty:** ⭐ Easy
**Breaking Changes:** None
**Time Estimate:** 2-4 hours

V2.0 already had readable syntax. Just add V5.1 features.

#### Migration Strategy

V2.0 code works perfectly in V5.1. Simply start using new features:

```lppo
// V2.0 code (works as-is)
pub proc main() -> Void {
    let own x: Int64 = 42;
    out x;
}

// Enhanced with V5.1 features
use std::collections::Vec;

pub proc main() -> Void {
    let own numbers: Vec<Int64> = vec![1, 2, 3, 4, 5];
    
    let own doubled: Vec<Int64> = numbers
        .iter()
        .map(|x| x * 2)
        .collect();
    
    out "Doubled:", doubled;
}
```

## Feature Adoption Guide

### High-Priority Features to Adopt First

#### 1. Collections (Vec, HashMap, HashSet)

**Why:** Replace manual array management with modern collections.

```lppo
// Old way (V5.0)
let own arr: Arr<Int64> = [1, 2, 3, 4, 5];

// New way (V5.1)
use std::collections::Vec;

let own vec: Vec<Int64> = vec![1, 2, 3, 4, 5];
vec.push(6);
vec.push(7);

let own sum: Int64 = vec.iter().sum();
```

#### 2. Error Handling (Result, Option)

**Why:** Better error handling with composable error types.

```lppo
// Old way (V5.0)
pub proc divide(a: Int64, b: Int64) -> Int64 {
    if b == 0 {
        // Hard to handle errors
        return 0; // ???
    }
    return a / b;
}

// New way (V5.1)
pub proc divide(a: Int64, b: Int64) -> Result<Int64, Str> {
    if b == 0 {
        return Err("Division by zero");
    }
    return Ok(a / b);
}

pub proc main() -> Void {
    let own result: Result<Int64, Str> = divide(10, 0);
    match result {
        Ok(value) => out "Result:", value,
        Err(msg) => out "Error:", msg,
    }
}
```

#### 3. Pattern Matching

**Why:** Cleaner conditional logic and destructuring.

```lppo
// Old way (V5.0)
pub proc handle_option(opt: Option<Int64>) -> Void {
    if opt.is_some() {
        let own val: Int64 = opt.unwrap();
        if val > 0 {
            out "Positive";
        } else {
            out "Non-positive";
        }
    } else {
        out "None";
    }
}

// New way (V5.1)
pub proc handle_option(opt: Option<Int64>) -> Void {
    match opt {
        Some(x) if x > 0 => out "Positive",
        Some(x) => out "Non-positive",
        None => out "None",
    }
}
```

#### 4. Iterators

**Why:** Functional programming with zero-cost abstractions.

```lppo
// Old way (V5.0)
pub proc process_numbers(arr: Arr<Int64>) -> Arr<Int64> {
    let own result: Arr<Int64> = [];
    let mut own i: Int64 = 0;
    
    while i < arr.length() {
        let own val: Int64 = arr[i];
        if val > 0 {
            let own doubled: Int64 = val * 2;
            result.push(doubled);
        }
        i = i + 1;
    }
    
    return result;
}

// New way (V5.1)
pub proc process_numbers(arr: Vec<Int64>) -> Vec<Int64> {
    return arr.iter()
        .filter(|x| x > 0)
        .map(|x| x * 2)
        .collect();
}
```

#### 5. Async/Await

**Why:** Non-blocking I/O without callback hell.

```lppo
// Old way (V5.0) - blocking
pub proc fetch_data() -> Str {
    // Blocks entire thread
    let own response: Response = http::get_blocking("https://api.example.com");
    return response.text();
}

// New way (V5.1) - non-blocking
pub async proc fetch_data() -> Result<Str, Error> {
    let own response: Response = await http::get("https://api.example.com")?;
    let own text: Str = await response.text()?;
    return Ok(text);
}
```

### Medium-Priority Features

#### Smart Pointers (Rc, Arc, Box)

```lppo
use std::rc::Rc;

pub proc share_data() -> Void {
    let own shared: Rc<Str> = Rc::new("Shared data");
    let own clone1: Rc<Str> = Rc::clone(ref shared);
    let own clone2: Rc<Str> = Rc::clone(ref shared);
    
    out "Refcount:", Rc::strong_count(ref shared); // 3
}
```

#### Closures

```lppo
pub proc main() -> Void {
    let own x: Int64 = 10;
    
    let own add_x = |y: Int64| -> Int64 {
        return x + y;
    };
    
    out add_x(5); // 15
}
```

#### Testing Framework

```lppo
#[test]
pub proc test_addition() -> Void {
    assert_eq!(2 + 2, 4);
}

#[test]
pub proc test_error_handling() -> Void {

}
```

## Common Migration Patterns

### Pattern 1: Error Propagation

```lppo
// Old: Manual error checking
pub proc read_file(path: Str) -> Str {
    let own file: File = File::open(path);
    if file.is_error() {
        return "";
    }
    return file.read_to_string();
}

// New: ? operator
pub proc read_file(path: Str) -> Result<Str, Error> {
    let own file: File = File::open(path)?;
    let own contents: Str = file.read_to_string()?;
    return Ok(contents);
}
```

### Pattern 2: Collection Operations

```lppo
// Old: Manual loops
pub proc sum_positive(arr: Arr<Int64>) -> Int64 {
    let mut own sum: Int64 = 0;
    let mut own i: Int64 = 0;
    
    while i < arr.length() {
        if arr[i] > 0 {
            sum = sum + arr[i];
        }
        i = i + 1;
    }
    
    return sum;
}

// New: Iterator methods
pub proc sum_positive(vec: Vec<Int64>) -> Int64 {
    return vec.iter()
        .filter(|x| x > 0)
        .sum();
}
```

### Pattern 3: Resource Management

```lppo
// Old: Manual cleanup
pub proc process_file(path: Str) -> Void {
    let own file: File = File::open(path);
    // ... use file ...
    file.close(); // Must remember!
}

// New: RAII (automatic cleanup)
pub proc process_file(path: Str) -> Result<Void, Error> {
    let own file: File = File::open(path)?;
    // ... use file ...
    // Automatically closed when file goes out of scope
    return Ok(());
}
```

### Pattern 4: Shared Data

```lppo
// Old: Complex manual sharing
pub proc share_data() -> Void {
    let own data: Str = "Shared";
    // Difficult to share without copying
}

// New: Smart pointers
use std::rc::Rc;

pub proc share_data() -> Void {
    let own data: Rc<Str> = Rc::new("Shared");
    let own clone1: Rc<Str> = Rc::clone(ref data);
    let own clone2: Rc<Str> = Rc::clone(ref data);
    // All share the same underlying data
}
```

## Performance Considerations

### Zero-Cost Abstractions

V5.1's iterators and combinators compile to the same efficient code as manual loops:

```lppo
// This high-level code...
numbers.iter()
    .filter(|x| x > 0)
    .map(|x| x * 2)
    .sum()

// ...compiles to this efficient loop
let mut sum = 0;
for x in numbers {
    if x > 0 {
        sum += x * 2;
    }
}
```

### When to Use Which Feature

| Feature | Performance | Use When |
|---------|------------|----------|
| Iterators | Zero-cost | Always (same as loops) |
| Smart pointers (Rc) | Small overhead | Need shared ownership |
| Smart pointers (Arc) | Atomic overhead | Thread-safe sharing |
| Async/await | Efficient | I/O-bound operations |
| Channels | Lock overhead | Thread communication |
| Closures | Zero-cost (inline) | Small, hot functions |
| Reflection | Runtime cost | Rarely, only when needed |

## Troubleshooting

### Issue: Build fails after upgrade

**Solution:** Clean and rebuild

```bash
cargo clean
cargo build --release
```

### Issue: Tests fail with new error types

**Solution:** Update error assertions

```lppo
// Old
assert!(matches!(err, LppoError::SomeError(msg)));

// New (if error structure changed)
assert!(matches!(err, LppoError::SomeError { message: msg, .. }));
```

### Issue: Performance regression

**Solution:** Check for unintended allocations or excessive cloning

```lppo
// Avoid
let own vec: Vec<Int64> = expensive_vec.clone(); // Unnecessary copy

// Prefer
let ref vec: ref Vec<Int64> = ref expensive_vec; // Borrow instead
```
