================================================================================
LPPO LANGUAGE - COMPLETE FEATURE & SYNTAX REFERENCE
================================================================================
Version: 5.3.0
File extensions: .lppo (implementation), .lpph / .lph (header)

This document describes every language feature, keyword, statement, expression,
built-in function, and file-convention supported by the LPPO compiler/runtime.

================================================================================
1. FILE ORGANIZATION & MULTI-FILE SUPPORT
================================================================================

LPPO programs can span multiple files. Imports use the `use` declaration and
are resolved relative to the directory of the source file being compiled.

  use math;                  // imports math.lppo / math.lpph / math.lph
  use std::inc;              // imports std/inc.lppo (nested path)
  use io::{read_file, write_file};

Resolution order (first match wins, implementation preferred over header):
  <root>/<path>.lppo
  <root>/<path>.lpph
  <root>/<path>.lph
  <root>/<path>/index.lppo
  <root>/<path>/index.lpph
  <root>/<path>/index.lph

Header files (.lpph / .lph):
  - Contain declaration-only procedures (empty bodies).
  - Used to share type/class/procedure declarations across files.
  - A header procedure is type-checked as a declaration but is NOT compiled
    into executable code unless a matching implementation (.lppo) exists.
  - If both a header and implementation define the same procedure, the
    implementation wins; two implementations of the same name is an error.
  - Nested imports are resolved relative to the same root directory.
  - Import cycles are detected and skipped automatically.

Compilation pipeline:
  parse -> resolve imports (merge) -> typecheck -> compile -> execute

Public API (lib.rs):
  build_executor(source) -> Executor
  build_executor_with_root(source, root) -> Executor
  compile_to_bytes(source) -> Vec<u8>   (JSON-serialized, embeddable)
  load_executor_from_bytes(bytes) -> Executor

CLI:
  cargo run -- <file.lppo>      # run a source file

================================================================================
2. LEXICAL ELEMENTS
================================================================================

Identifiers:
  - Start with a letter (a-z, A-Z) or underscore (_).
  - May contain letters, digits, and underscores.
  - Case-sensitive.

Literals:
  - Integer:   42, -7, 0
  - Float:     3.14, -2.5
  - String:    "hello", "line1\nline2", supports \n \r \t \" \\
  - Boolean:   true, false

Comments:
  - Not supported by the lexer (whitespace and newlines are skipped).

Operators / punctuation:
  +  -  *  /  %  ^(pow)      arithmetic
  == != < <= > >=            comparison
  &&  ||  !                  logical  (keywords: and, or, not)
  &  |  ^                    bitwise
  (  )  [  ]  {  }  ;  ,  :  .  ->  ::  =

================================================================================
4. TYPES & TYPE ANNOTATIONS
================================================================================

Every variable and parameter requires an explicit type annotation:

  let own x: Int64 = 42;
  let own name: Str = "Alice";
  let own flag: Bool = true;
  let own items: Arr<Int64> = [1, 2, 3];
  let own opt: Option<Str> = ...;
  let own res: Result<Int64, Str> = ...;
  let own nothing: Void = ...;

Type annotations:
  Int64       signed 64-bit integer
  Bool        boolean (true/false)
  Str         string
  Void        no return value
  Arr<T>      array of T
  Option<T>   optional value
  Result<T,E> result or error
  Custom(String)   user-defined struct/class type
  Generic(String, Vec<T>)  generic parameterized type
  Tuple(Vec<T>)            tuple type
  Ref<T,'a> / Mut<T> / Own<T>   reference / mutable / owned

Procedures are declared with params and a return type:

  proc add(a: Int64, b: Int64) -> Int64 {
      return a + b;
  }

  pub proc main() -> Void {
      // entry point
  }

`pub` marks a procedure/struct as publicly exported.
`unsafe` marks a procedure as unsafe.

================================================================================
5. STATEMENTS
================================================================================

5.1 Output
  out expr1, expr2, ...;        // print expressions, space-separated, newline
  print expr1, ...;             // print without newline (built-in call)
  println expr1, ...;           // print with newline (built-in call)
  eprintln expr1, ...;          // print to stderr
  parallel expr1, expr2, ...;   // emit expressions in parallel

5.2 Input
  input var: Type with "prompt";    // read typed stdin input
  // Supported types: Int64, Bool, Str

5.3 Variable declaration
  let own name: Type = expr;        // owned, immutable by default
  let mut name: Type = expr;        // mutable binding
  // `own` / `ref` / `borrow` ownership qualifiers; `mut` for mutability.
  // Type annotation is mandatory.

5.4 Conditionals
  if cond {
      statements
  } elif cond {
      statements
  } else {
      statements
  }

5.5 Loops
  while cond { statements }
  for var: Type in iterable { statements }
  loop { statements }          // infinite loop
  break;                       // exit loop
  continue;                    // next iteration

5.6 Return
  return;              // return Void / unit
  return expr;         // return a value

5.7 Memory
  alloc<Type> on heap [size];    // allocate (size for arrays)
  dealloc var;                   // free
  move source to target;         // transfer ownership
  copy source to target;         // copy value
  borrow<'a> var;                // borrow
  ref var;                        // take reference
  deref expr;                    // dereference
  sizeof<Type>;                  // size of type
  alignof<Type>;                 // alignment
  cast<ToType>(expr);            // type cast
  unsafe { statements }          // unsafe block

5.8 Scope
  scope { statements }           // explicit scope block
  end                            // end marker

5.9 Match
  match expr {
      pattern => expr,
      ...
  }

5.10 Assignment
  var = expr;                    // reassign whole variable (LPPO does NOT
                                 // support per-field struct assignment;
                                 // rebind the whole variable instead)
  arr[index] = expr;             // indexed assignment (limited support)

5.11 Struct instantiation (expression)
  let own p: Point = Point { x: 10, y: 20 };   // struct/class literal

5.12 Pause (async)
  pause [prompt: expr] [timeout_ms: expr] [until: expr]
         [assign_to: var] [on_mismatch: expr] [on_timeout: expr];

6. EXPRESSIONS
================================================================================

6.1 Literals
  42                      integer
  3.14                    float
  "hello"                 string
  true / false            boolean

6.2 Variables
  name                    simple variable
  module::name            qualified variable

6.3 Arithmetic
  a + b   a - b   a * b   a / b   a % b   a ^ b (pow)

6.4 Comparison

6.5 Logical / bitwise

  a & b     a | b    a ^ b

6.6 Arrays

6.7 Field access & method calls
  obj.field                       field access
  obj.method(arg1, arg2)          method call

6.8 Function calls
  func(arg1, arg2)                procedure call; return value usable in expr

6.9 Closures / lambdas
  \|params\| -> Type { body }     closure expression

6.10 Ranges
  start..end                      range expression

6.11 Struct instantiation
  Point { x: 10, y: 20 }          struct/class literal expression

6.12 Reference / cast / sizeof
  ref var, deref expr, sizeof<Type>, alignof<Type>, cast<T>(expr)

================================================================================
7. DATA STRUCTURES: STRUCTS, CLASSES, ENUMS, TRAITS
================================================================================

7.1 Struct
  struct Point {
      x: Int64,
      y: Int64,
  }

7.2 Class (new - instantiable struct)
  class Point {
      x: Int64,
      y: Int64,
  }

  // Instantiation as an expression:
  let own p: Point = Point { x: 3, y: 4 };
  out p.x, p.y;      // field access works

7.3 Enum
  enum Color {
      Red,
      Green,
      Blue,
  }

7.4 Trait
  trait Drawable {
      draw: ...;
  }

7.5 Impl
  impl Drawable for Point { ... }

Note: Classes are parsed as struct types and reuse the existing field,
method, and field-access machinery. Individual field reassignment (p.x = 5)
is NOT supported; rebind the whole variable:
  p = Point { x: 5, y: p.y };

  str_len(s: Str) -> Int64

8.4 Math
  abs(i: Int64) -> Int64
  min(a: Int64, b: Int64) -> Int64
  max(a: Int64, b: Int64) -> Int64
  pow(base: Int64, exp: Int64) -> Int64   (exp >= 0)

8.5 JSON
  json_parse(s: Str) -> Str

8.6 System
  system(command: Str) -> Str     // run shell command, return combined output

8.7 Color / ANSI
  color(text: Str, style: Str) -> Str
      // Wraps text in ANSI codes, resets at end.
      // style accepts:
      //   * single name: "red", "bold", "underline"
      //   * combined (space/comma): "bold underline red", "bold,italic,green"
      //   * raw SGR codes: "1", "1;31", "4;33"
      //   * raw escape: "\x1b[1;31m"
      // Names: reset, bold, dim, italic, underline, blink, reverse, hidden,
      //        black, red, green, yellow, blue, magenta, cyan, white,
      //        bright_black..bright_white
      // Example: color("hello", "bold underline cyan") -> \x1b[1;4;36mhello\x1b[0m

8.8 Terminal User Interface (TUI) - ANSI escape based, dependency-free
  tui_init() -> Int64           // enter alt screen, hide cursor, clear
  tui_end() -> Int64            // restore screen, show cursor
  tui_clear() -> Int64          // clear screen + home cursor
  tui_move(x: Int64, y: Int64) -> Int64      // move cursor to (x,y)
  tui_put(text: Str, x: Int64, y: Int64) -> Int64   // place text at (x,y)
  tui_puts(text: Str, x: Int64, y: Int64, color: Str) -> Int64   // colored text at (x,y)
  tui_cls(x: Int64, y: Int64, w: Int64, h: Int64) -> Int64   // clear rectangular region
  tui_box(x: Int64, y: Int64, w: Int64, h: Int64, title: Str) -> Int64   // draw bordered box
  tui_label(text: Str, x: Int64, y: Int64) -> Int64   // plain label at (x,y)
  tui_title(title: Str) -> Int64   // set terminal window title
  tui_fg(color: Str) -> Int64      // set foreground color (prefix stays active)
  tui_bg(color: Str) -> Int64      // set background color
  tui_bold(on: Int64) -> Int64     // bold on (1) / off (0)
  tui_underline(on: Int64) -> Int64 // underline on (1) / off (0)
  tui_reverse(on: Int64) -> Int64  // reverse video on/off
  tui_style(style: Str) -> Int64   // apply combined style string
  tui_reset() -> Int64             // reset all attributes
  tui_hide_cursor() -> Int64
  tui_show_cursor() -> Int64
  tui_refresh() -> Int64           // flush stdout
  tui_input(prompt: Str, x: Int64, y: Int64, w: Int64) -> Str   // read line at position
  tui_getch() -> Str               // read single character
  tui_poll() -> Str                // read a line (blocking)
  tui_progress(value: Int64, max: Int64, x: Int64, y: Int64, w: Int64) -> Int64  // progress bar
  tui_size() -> Arr<Int64>         // [rows, cols] via tput (fallback 24x80)

Example TUI usage:
  tui_init();
  tui_box(8, 5, 50, 12, "Welcome");
  tui_puts("Hello", 10, 7, "bold cyan");
  tui_progress(45, 100, 10, 13, 30);
  let own choice: Str = tui_input("Pick: ", 10, 16, 20);
  tui_end();

  Value::Int(i64)

================================================================================
10. TYPECHECKING
================================================================================

- All variables/parameters require explicit type annotations.
- Procedure arity is checked at call sites.
- Struct field access is resolved against the struct definition; field
  existence and types are verified.
- Struct instantiation validates that all provided fields exist and match
  declared types (extra fields are ignored; missing fields allowed at
  runtime, defaulting to zero/empty).
- Return types are checked against `return expr`.
- `use` imports are merged; duplicate declarations across files are
  deduplicated (implementation overrides header).

================================================================================
12. COMPILATION & EXECUTION
================================================================================

  cargo build                   # build the compiler/runtime
  cargo test                    # run the test suite
  cargo clippy --all-targets    # lint
  cargo run -- <file.lppo>      # compile and run a program

Program structure:
  - One `pub proc main() -> Void` entry point is required to run.
  - Multiple procedures may be defined; only `main` is executed by `run()`.
  - Procedures can call other procedures defined anywhere in the merged
    program (including across imported files).
  - Procedures can be called as expressions; their return value is captured:
      let own x: Int64 = add(10, 20);

State threading pattern (LPPO rebinds whole variables):
  Because per-field struct assignment is not supported, state is threaded
  by having procedures take a struct and return a new one:
      gs = explore_turn(gs);
      gs = combat_turn(gs);
