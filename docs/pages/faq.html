Frequently Asked Questions

Common questions and troubleshooting for LPPO

General Questions

What is LPPO?

LPPO (Lightweight Procedural & Parallel Output) is a feature-rich programming language that combines procedural structure with parallel execution capabilities. It's designed to be easy to learn while providing powerful features like arrays, control flow, operators, and native parallel execution.

Who created LPPO?

LPPO is an open-source project developed as a demonstration of modern language implementation techniques using Rust.

Why was LPPO created?

LPPO was created to explore:

  • Clean procedural programming design
  • Native parallel execution features
  • Modern compiler/interpreter architecture
  • Memory-safe language implementation using Rust

Is LPPO production-ready?

LPPO v1.0 is feature-complete and stable for its intended use cases. However, it's primarily an educational and experimental language. For production systems, consider established languages with larger ecosystems and community support.

Installation & Setup

What are the system requirements?

  • Rust 1.80 or higher
  • Cargo (comes with Rust)
  • Any operating system supported by Rust (Windows, Linux, macOS)

How do I install Rust?

Visit rustup.rs and follow the installation instructions for your operating system.

The build is failing. What should I do?

Common solutions:

  • Ensure Rust is up to date: rustup update
  • Clean the build: cargo clean then rebuild
  • Check that you're using Rust 1.80 or higher: rustc --version
  • Report the issue on GitHub with error details

Language Features

Does LPPO support return values from procedures?

Currently, LPPO procedures do not return values. Data sharing between procedures is done through the shared environment. Future versions may add return value support.

Can I use LPPO for file I/O?

LPPO v1.0 does not include file I/O operations. The language focuses on computation and output. File I/O is planned for future versions.

Does LPPO have a module/import system?

Not currently. All procedures must be defined in a single file. A module system is planned for future releases.

What about error handling?

LPPO provides basic error reporting for runtime errors like division by zero and type mismatches. There are no user-facing error handling constructs (try/catch) in v1.0.

Can procedures be recursive?

Yes! You can write recursive procedures:

proc factorial(n) {
    if n <= 1 {
        out 1;
    } else {
        let prev = n - 1;
        call factorial(prev);
    }
}

However, without return values, you'll need to manage results through the environment or output.

Are there functions/lambdas?

No, LPPO only supports procedures. First-class functions and lambdas are not currently supported but are planned for future versions.

Syntax Questions

Do I need semicolons?

Yes, every statement must end with a semicolon:

let x = 10;
out "Hello";
call myproc;

Are variables mutable?

Variables can be reassigned by using another let statement:

let x = 10;
let x = x + 1;  // x is now 11

What's the difference between not and !?

They're the same - both perform logical NOT. Use not as a keyword or ! as an operator:

let flag = true;
out not flag;  // false
out !flag;     // false

How do I create multi-line strings?

Use escape sequences like \n:

let text = "Line 1\nLine 2\nLine 3";
out text;

Can I compare strings?

Yes, strings can be compared using == and !=:

let a = "hello";
let b = "world";
if a == b {
    out "Same";
} else {
    out "Different";
}

Arrays and Strings

Can arrays contain mixed types?

Yes! Arrays can contain any combination of integers, strings, booleans, and even other arrays:

let mixed = [1, "two", true, [4, 5]];
out mixed;

How do I get array length?

Use the .len() method:

let arr = [1, 2, 3, 4, 5];
out arr.len();  // 5

Can I modify arrays after creation?

Arrays are immutable once created. To "modify" an array, you would need to create a new one:

let arr = [1, 2, 3];
let arr = arr + [4, 5];  // [1, 2, 3, 4, 5]

What happens if I access an invalid index?

Accessing an out-of-bounds index will cause a runtime error:

let arr = [1, 2, 3];
out arr[10];  // Runtime error!

Can I slice arrays?

Not in v1.0. You can only access individual elements. Array slicing is planned for future versions.

Parallel Execution

How does parallel execution work?

Statements in a parallel block execute concurrently in separate threads. The program waits for all threads to complete before continuing.

Is execution order guaranteed in parallel blocks?

No! The order of execution is non-deterministic. Each statement runs in its own thread.

Can parallel blocks be nested?

Yes, you can nest parallel blocks:

parallel {
    out "Outer 1";
    parallel {
        out "Inner 1";
        out "Inner 2";
    }
    out "Outer 2";
}

Are there race conditions?

Each thread in a parallel block has its own copy of the environment at that point. Variables modified in one thread don't affect others, preventing traditional race conditions.

How many threads are created?

One thread per statement in the parallel block. Each thread is automatically joined before the program continues.

Performance

How fast is LPPO?

LPPO is an interpreted language using a tree-walking interpreter. It's fast enough for scripting and educational purposes but not optimized for high-performance computing.

Can I compile LPPO programs?

Yes! Use the --compile-out flag to create standalone executables:

cargo run -- --compile-out myapp.exe program.lppo

Note: This bundles the interpreter with your program; it's not native code compilation.

Are there optimization flags?

The LPPO runtime doesn't have optimization flags. Use cargo build --release for an optimized LPPO interpreter.

Troubleshooting

My program runs but produces no output

Common causes:

  • Missing proc main - Every program needs a main procedure
  • No out statements in your code
  • Logic errors preventing code execution

"Procedure not found" error

Ensure:

  • The procedure is defined before being called
  • The procedure name matches exactly (case-sensitive)
  • You're using call procedure_name syntax

"Unexpected token" error

Check:

  • All statements end with semicolons
  • Braces are balanced {}
  • Strings are properly closed with quotes
  • No reserved keywords used as identifiers

Division by zero

LPPO checks for division by zero at runtime and produces an error. Always validate divisors:

if divisor != 0 {
    let result = numerator / divisor;
    out result;
} else {
    out "Cannot divide by zero!";
}

Type mismatch errors

Operations require compatible types. For example:

// Error: can't add string to integer
let result = 5 + "hello";

// Correct: concatenate strings
let greeting = "Hello " + "World";

Development

Where are the tests?

Run tests with:

cargo test

Example programs in examples/ serve as integration tests.

How do I debug my LPPO program?

Use debug mode to see compilation and execution details:

cargo run -- --debug program.lppo

Can I embed LPPO in my application?

Yes! LPPO is written as a Rust library. You can use it programmatically:

use lppo::{lexer, parser, compiler, runtime};

let source = "proc main { out \"Hello\"; }";
let tokens = lexer::tokenize(source)?;
let ast = parser::parse(tokens)?;
let ops = compiler::compile(ast)?;
runtime::execute(ops)?;

Future Plans

What features are planned?

Potential future enhancements include:

  • Return values from procedures
  • Structs and custom types
  • First-class functions and lambdas
  • Module/import system
  • File I/O operations
  • Error handling constructs
  • More collection types (maps, sets)
  • Standard library
  • Language server protocol support

Will LPPO get a JIT compiler?

Possibly! A JIT compiler could significantly improve performance, but it's not currently planned for the near future.

Are there plans for a package manager?

A package manager would require a module system first. Both are under consideration for future versions.
