Implementation details and architecture of the LPPO interpreter

Architecture Overview

LPPO is implemented in Rust and follows a traditional compiler/interpreter architecture with the following stages:

  1. Lexical Analysis - Tokenization of source code
  2. Parsing - Construction of Abstract Syntax Tree (AST)
  3. Compilation - Lowering AST to runtime operations
  4. Execution - Interpretation of operations

Module Structure

Converts raw source code into a stream of tokens.

Key Types

pub struct Lexer {
    input: Vec<char>,
    position: usize,
}

pub enum Token {
    // Keywords
    Proc, Let, Out, If, Elif, Else,
    While, For, In, Loop, Break, Continue,
    Call, Parallel, Return,
    
    // Literals
    Integer(i64),
    String(String),
    True, False,
    
    // Identifiers and operators
    Identifier(String),
    Plus, Minus, Star, Slash,
    // ... more operators
}

Key Functions

  • new(input: String) -> Lexer - Creates a new lexer
  • tokenize() -> Result<Vec<Token>> - Tokenizes the input
  • next_token() -> Option<Token> - Returns the next token

Defines the data structures for representing LPPO programs.

Statement Types

    Out { values: Vec<Expr> },

        condition: Expr,
        body: Vec<Statement>,

    For {
        var: String,

    },
    Loop { body: Vec<Statement> },
    Break,
    Continue,
    Call { name: String, args: Vec<Expr> },

Expression Types

        left: Box<Expr>,

parser.rs - Parser

Constructs an Abstract Syntax Tree from tokens.

Key Functions

  • parse(tokens: Vec<Token>) -> Result<Vec<Procedure>>
  • parse_procedure() -> Result<Procedure>
  • parse_statement() -> Result<Statement>
  • parse_expression() -> Result<Expr>

Precedence Levels

Expression parsing follows standard operator precedence:

  1. parse_or() - Lowest precedence
  2. parse_and()
  3. parse_equality()
  4. parse_comparison()
  5. parse_bitwise()
  6. parse_add_sub()
  7. parse_mul_div()
  8. parse_power()
  9. parse_unary()
  10. parse_postfix()
  11. parse_primary() - Highest precedence

Command-Line Interface

Usage

lppo [OPTIONS] <file.lppo>

Options

Option Description
--debug Enable diagnostic output
--compile-out <file> Compile to standalone executable

Binary Bundling

LPPO can compile programs into standalone executables that bundle the runtime:

Process

  1. Parse and compile the LPPO source
  2. Serialize compiled operations to JSON
  3. Embed JSON into executable using build script
  4. Runtime loads and executes embedded operations

Implementation

cargo run -- --compile-out myapp.exe program.lppo

This creates a self-contained executable with:

  • The LPPO runtime
  • Your compiled program
  • No external dependencies

Parallel Execution

Parallel blocks use Rust's threading model:

// Simplified implementation
std::thread::scope(|s| {
    for statement in parallel_block {
        s.spawn(|| execute_statement(statement));
    }
    // Automatically joins all threads
});

Characteristics

  • Each statement runs in its own thread
  • Execution order is non-deterministic
  • All threads complete before continuing
  • Thread-safe through Rust's ownership system

Type System

LPPO is dynamically typed with runtime type checking:

Type Coercion

  • No automatic type coercion
  • Operations require compatible types
  • Runtime errors for type mismatches

Truthiness

Values evaluate to boolean in conditional contexts:

  • false, 0 → false
  • Everything else → true

Performance

Optimization Opportunities

  • Constant folding
  • Dead code elimination
  • Inline procedure calls
  • Loop unrolling
  • Tail call optimization

Current Implementation

  • Tree-walking interpreter
  • No JIT compilation
  • Direct AST execution
  • Hash-based variable lookup

Memory Model

LPPO inherits Rust's memory safety guarantees:

  • No manual memory management
  • Automatic garbage collection via Rust's ownership
  • No dangling pointers
  • No buffer overflows

Extension Points

Adding Built-in Functions

  1. Add to lexer keyword list
  2. Add to AST expression types
  3. Implement in runtime evaluator

Adding Operators

  1. Add token to lexer
  2. Add to BinaryOp/UnaryOp enum
  3. Add to parser precedence chain
  4. Implement evaluation in runtime

Adding Control Structures

  1. Add keywords to lexer
  2. Add statement variant to AST
  3. Add parsing function
  4. Add compilation logic
  5. Add runtime execution
