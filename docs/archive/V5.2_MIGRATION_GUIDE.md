# LPPO V5.2 Migration Guide

## Migrating to LPPO V5.2

This guide helps you migrate your LPPO code to V5.2, which adds **570+ new features** on top of V5.1's 660 features for a total of **1,230+ features**.

## Key Highlights

- ✅ **100% Backward Compatible** - All V5.1, V5.0, V4.0, V3.0, and V2.0 code works unchanged
- ✅ **No Breaking Changes** - Existing code continues to work
- ✅ **Gradual Adoption** - Use new features at your own pace
- ✅ **Enhanced Performance** - SIMD, GPU, and JIT improvements
- ✅ **New Capabilities** - Effect system, linear types, advanced async

```lppo
// V5.2 - SIMD vectorization (4-8x faster)
use std::simd::F32x4;

pub proc add_arrays_simd(a: Arr<F32>, b: Arr<F32>) -> Arr<F32> {
    let mut own result: Arr<F32> = allocate_array<F32>(a.len());
    let mut own i: Int64 = 0;
    
    // Process 4 elements at a time
    while i + 4 <= a.len() {
        let own va: F32x4 = F32x4::load_from_slice(a, i);
        let own vb: F32x4 = F32x4::load_from_slice(b, i);
        let own vr: F32x4 = va + vb;
        vr.store_to_slice(result, i);
        i = i + 4;
    }
    
    // Handle remaining elements
    while i < a.len() {
        result[i] = a[i] + b[i];
        i = i + 1;
    }
    
    return result;
}
```

```lppo
use std::gpu::{Kernel, cuda_malloc, cuda_memcpy_to_device, cuda_free};

#[kernel]
pub proc matrix_multiply_gpu(a: Arr<F32>, b: Arr<F32>, c: Arr<F32>, n: Int64) -> Void {
    let own idx: Int64 = block.x * block.dim.x + thread.x;
    let own idy: Int64 = block.y * block.dim.y + thread.y;
    
    if idx < n and idy < n {
        let mut own sum: F32 = 0.0;
        let mut own k: Int64 = 0;
        while k < n {
            sum = sum + a[idy * n + k] * b[k * n + idx];
            k = k + 1;
        }
        c[idy * n + idx] = sum;
    }
}

pub proc main() -> Void {

    let own result: Arr<F32> = run_on_gpu(n);
}
```

### 5. Effect System (10+ features)

```lppo
effect State<S> {

effect Logger {
    proc log(message: Str) -> Void;
}

pub proc stateful_computation() -> Int64 with State<Int64>, Logger {
    perform Logger::log("Starting computation");
    let own current: Int64 = perform State::get();
    perform State::put(current + 10);
    return current + 10;
}

pub proc main() -> Void {
    let own result: Int64 = handle stateful_computation() 
        with State<Int64> {
            initial = 0,
            get() => initial,
            put(x) => { initial = x; resume (); },
        }
        with Logger {
            log(msg) => { out "[LOG]", msg; resume (); },
        };
    
    out "Result:", result;
}
```

#### Pattern 1: Parallel Processing

```lppo
    }

    return items
        .par_iter()
        .map(|item: Item| -> Result { return process_item(item); })
        .collect();
```

#### Pattern 2: Error Handling

```lppo
// V5.1 - Match-based error handling
pub proc read_config() -> Result<Config, Error> {
    match File::open("config.toml") {
        Ok(file) => {
            match file.read_to_string() {
                Ok(contents) => {
                    match parse_toml(contents) {
                        Ok(config) => return Ok(config),
                        Err(e) => return Err(e),
                    }
                },
                Err(e) => return Err(e),
            }
        },
        Err(e) => return Err(e),
    }
}

// V5.2 - ? operator with context
pub proc read_config() -> Result<Config, Error> {
    let own file: File = File::open("config.toml")
        .context("Failed to open config file")?;
    let own contents: Str = file.read_to_string()
        .context("Failed to read config file")?;
    let own config: Config = parse_toml(contents)
        .context("Failed to parse config")?;
    return Ok(config);
}
```

#### Pattern 3: Async Operations

```lppo
// V5.1 - Blocking I/O
pub proc fetch_all_users(ids: Vec<UserId>) -> Vec<User> {
    let own users: Vec<User> = Vec::new();
    for id: UserId in ids {
        let own user: User = fetch_user_blocking(id);
        users.push(user);
    }
    return users;

// V5.2 - Async/await with concurrency
pub async proc fetch_all_users(ids: Vec<UserId>) -> Vec<User> {
    let own tasks: Vec<Task<User>> = ids
        .iter()
        .map(|id: UserId| -> Task<User> {
            return spawn_async(fetch_user_async(id));
        })
        .collect();
    
    let own users: Vec<User> = Vec::new();
    for task: Task<User> in tasks {
        users.push(await task.join());
    }
    return users;
}
```

## Performance Tips

### 1. Use SIMD for Numeric Computation

```lppo
// When processing large arrays of floats/ints, use SIMD
use std::simd::F32x4;

pub proc process_array(data: Arr<F32>) -> Arr<F32> {
    // Process 4 elements at a time
    let mut own i: Int64 = 0;
    while i + 4 <= data.len() {
        let own vec: F32x4 = F32x4::load_from_slice(data, i);
        let own result: F32x4 = vec * vec + vec;
        result.store_to_slice(data, i);
        i = i + 4;
    }
    return data;
}
```

## Troubleshooting

### Issue: SIMD code doesn't compile

**Solution**: Ensure you're using the correct SIMD types and that your target platform supports the SIMD instructions.

```lppo
// Check target capabilities
#[cfg(target_feature = "sse4.2")]
pub proc use_simd() -> Void {
    // SIMD code here
}

#[cfg(not(target_feature = "sse4.2"))]
pub proc use_simd() -> Void {
    // Fallback scalar code
}
```

### Issue: Effect handlers are confusing

**Solution**: Start with simple effects like State or Logger, then gradually build up to more complex combinations.

```lppo
// Start simple
effect State<S> {
    proc get() -> S;
    proc put(new_state: S) -> Void;
}

// Then combine
pub proc complex() -> Int64 with State<Int64>, Logger {
    // Use both effects
}
```

### Issue: Linear types prevent code from compiling

**Solution**: Understand that linear types must be consumed exactly once. Use `clone()` if you need multiple uses.

```lppo
// Won't compile - used twice
let own file: FileHandle = open("test.txt");
write(file, "data");
close(file);  // file consumed
close(file);  // ERROR: file already consumed

// Fix - clone if needed (but defeats the purpose)
let own file: FileHandle = open("test.txt");
let own file2: FileHandle = file.clone();  // If cloneable
close(file);
close(file2);

// Better - use properly
let own file: FileHandle = open("test.txt");
write(file, "data");
close(file);  // Properly consumed once
```
