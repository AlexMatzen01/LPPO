## Code Style

### Naming Conventions

```lppo
// Procedures: snake_case
pub proc calculate_total(items: Vec<Int64>) -> Int64 { ... }

// Types: PascalCase
pub struct UserAccount { ... }
pub enum PaymentStatus { ... }

// Constants: UPPER_SNAKE_CASE
let own MAX_CONNECTIONS: Int64 = 100;

// Variables: snake_case
let own user_count: Int64 = 42;
```

### Indentation and Formatting

```lppo
// Use 4 spaces for indentation
pub proc main() -> Void {
    if condition {
        do_something();
    } else {
        do_something_else();
    }
}

// Line length: prefer < 100 characters
// Break long lines at logical points
let own result: Vec<Int64> = numbers
    .iter()
    .filter(|x| x > 0)
    .map(|x| x * 2)
    .collect();
```

### Comments

```lppo
// Single-line comments for brief explanations
let own count: Int64 = 42; // Initialize counter

// Multi-line comments for detailed explanations
/*
 * This procedure processes user input and validates
 * it against the schema before storing in the database.
 */
pub proc process_input(data: Str) -> Result<Void, Error> {
    ...
}

// Doc comments for public APIs
/// Calculates the sum of all numbers in the vector.
/// 
/// # Arguments
/// * `numbers` - Vector of integers to sum
/// 
/// # Returns
/// Total sum of all numbers
pub proc sum(numbers: Vec<Int64>) -> Int64 {
    return numbers.iter().sum();
}
```

## Type System

### Always Use Explicit Types

```lppo
// ✅ Good: Explicit type annotation
let own count: Int64 = 0;
let own users: Vec<User> = Vec::new();

// ❌ Bad: Missing type (won't compile)
// let own count = 0;
```

### Prefer Specific Types Over Generic

```lppo
// ✅ Good: Specific type
pub proc get_user_id(user: User) -> Int64 {
    return user.id;
}

// ❌ Less clear: Generic parameter
pub proc get_id<T>(item: T) -> Int64 {
    return item.id; // What if T doesn't have id?
}
```

### Use Type Aliases for Clarity

```lppo
// Define type aliases for complex types
type UserId = Int64;
type UserMap = HashMap<UserId, User>;
type ResultStr = Result<Str, Error>;

// Use aliases in code
pub proc find_user(id: UserId, users: UserMap) -> Option<User> {
    return users.get(id);
}
```

### Leverage Pattern Matching

```lppo
// ✅ Good: Exhaustive pattern matching
match result {
    Ok(value) => process(value),
    Err(error) => handle_error(error),
}

// ❌ Bad: Ignoring error case
let own value: T = result.unwrap(); // Panics on error!
```

## Error Handling

### Use Result for Fallible Operations

```lppo
// ✅ Good: Returns Result
pub proc read_config(path: Str) -> Result<Config, Error> {
    let own file: File = File::open(path)?;
    let own contents: Str = file.read_to_string()?;
    let own config: Config = parse_config(contents)?;
    return Ok(config);
}

// ❌ Bad: Panics on error
pub proc read_config(path: Str) -> Config {
    let own file: File = File::open(path).unwrap(); // Panic!
    ...
}
```

### Use Option for Nullable Values

```lppo
// ✅ Good: Returns Option
pub proc find_user(id: Int64) -> Option<User> {
    if user_exists(id) {
        return Some(get_user(id));
    }
    return None;
}

// ❌ Bad: Returns sentinel value
pub proc find_user(id: Int64) -> User {
    if user_exists(id) {
        return get_user(id);
    }
    return NULL_USER; // Sentinel value is error-prone
}
```

### Use ? Operator for Error Propagation

```lppo
// ✅ Good: Clean error propagation
pub proc process_data() -> Result<Void, Error> {
    let own data: Str = read_file("data.txt")?;
    let own parsed: Data = parse_data(data)?;
    store_data(parsed)?;
    return Ok(());
}

// ❌ Bad: Manual error checking
pub proc process_data() -> Result<Void, Error> {
    let own result1: Result<Str, Error> = read_file("data.txt");
    if result1.is_err() {
        return Err(result1.unwrap_err());
    }
    let own data: Str = result1.unwrap();
    // ... more manual checking ...
}
```

### Provide Meaningful Error Messages

```lppo
// ✅ Good: Descriptive error
if not file_exists(path) {
    return Err("File not found: " + path);
}

// ❌ Bad: Generic error
if not file_exists(path) {
    return Err("Error");
}
```

## Collections

### Choose the Right Collection

```lppo
// Use Vec for ordered, indexed access
let own items: Vec<Int64> = vec![1, 2, 3];

// Use HashMap for key-value lookups
let own ages: HashMap<Str, Int64> = HashMap::new();

// Use HashSet for unique values
let own unique_ids: HashSet<Int64> = HashSet::new();

// Use LinkedList for frequent insertions/deletions
let own queue: LinkedList<Task> = LinkedList::new();
```

### Pre-allocate Capacity When Possible

```lppo
// ✅ Good: Pre-allocate if size is known
let mut own vec: Vec<Int64> = Vec::with_capacity(1000);
for i in 0..1000 {
    vec.push(i);
}

// ❌ Less efficient: Multiple reallocations
let mut own vec: Vec<Int64> = Vec::new();
for i in 0..1000 {
    vec.push(i); // May reallocate multiple times
}
```

### Use Iterators Over Index Loops

```lppo
// ✅ Good: Iterator
let own sum: Int64 = numbers.iter().sum();

// ❌ Less idiomatic: Manual loop
let mut own sum: Int64 = 0;
let mut own i: Int64 = 0;
while i < numbers.len() {
    sum = sum + numbers[i];
    i = i + 1;
}
```

### Chain Iterator Operations

```lppo
// ✅ Good: Chained operations
let own result: Vec<Int64> = numbers
    .iter()
    .filter(|x| x > 0)
    .map(|x| x * 2)
    .take(10)
    .collect();

// ❌ Less efficient: Multiple intermediate collections
let own positive: Vec<Int64> = numbers.iter()
    .filter(|x| x > 0)
    .collect();
let own doubled: Vec<Int64> = positive.iter()
    .map(|x| x * 2)
    .collect();
let own result: Vec<Int64> = doubled.iter()
    .take(10)
    .collect();
```

## Memory Management

### Prefer Owned Values

```lppo
// ✅ Good: Clear ownership
let own data: Str = "Hello";
let own numbers: Vec<Int64> = vec![1, 2, 3];
```

### Use References When Appropriate

```lppo
// ✅ Good: Pass by reference when not transferring ownership
pub proc print_vec(vec: ref Vec<Int64>) -> Void {
    for item in vec {
        out item;
    }
}

pub proc main() -> Void {
    let own numbers: Vec<Int64> = vec![1, 2, 3];
    print_vec(ref numbers); // Still own numbers after call
    out numbers.len(); // Can still use numbers
}
```

### Use Smart Pointers for Shared Ownership

```lppo
use std::rc::Rc;

// ✅ Good: Rc for shared ownership (single-threaded)
let own shared: Rc<Data> = Rc::new(expensive_data);
let own clone1: Rc<Data> = Rc::clone(ref shared);
let own clone2: Rc<Data> = Rc::clone(ref shared);

// For multi-threaded: use Arc
use std::sync::Arc;
let own thread_safe: Arc<Data> = Arc::new(expensive_data);
```

### Avoid Unnecessary Clones

```lppo
// ✅ Good: Borrow instead of clone
pub proc process(data: ref Str) -> Void {
    out data;
}

let own text: Str = "Hello";
process(ref text);

// ❌ Bad: Unnecessary clone
pub proc process(data: Str) -> Void {
    out data;
}

let own text: Str = "Hello";
process(text.clone()); // Extra allocation!
```

## Concurrency

### Use Message Passing Over Shared State

```lppo
// ✅ Good: Message passing with channels
use std::sync::channel;

let own (tx, rx): (Sender<Int64>, Receiver<Int64>) = channel();

thread::spawn(move || {
    tx.send(42);
});

let own value: Int64 = rx.recv().unwrap();
```

### Protect Shared State with Mutex

```lppo
// ✅ Good: Mutex for shared mutable state
use std::sync::{Arc, Mutex};

let own counter: Arc<Mutex<Int64>> = Arc::new(Mutex::new(0));

// Spawn threads that share counter
for i in 0..10 {
    let own counter_clone: Arc<Mutex<Int64>> = Arc::clone(ref counter);
    thread::spawn(move || {
        let mut own num: ref mut Int64 = counter_clone.lock().unwrap();
        *num += 1;
    });
}
```

### Keep Lock Scopes Small

```lppo
// ✅ Good: Short lock scope
{
    let mut own data: ref mut Data = mutex.lock().unwrap();
    data.update();
} // Lock released here
process_something_else();

// ❌ Bad: Long lock scope
let mut own data: ref mut Data = mutex.lock().unwrap();
data.update();
process_something_else(); // Still holding lock!
// Lock held longer than necessary
```

### Use Async for I/O-Bound Operations

```lppo
// ✅ Good: Async for I/O
pub async proc fetch_all() -> Result<Vec<Str>, Error> {
    let own futures: Vec<Future<Result<Str, Error>>> = vec![
        fetch_url("https://api1.example.com"),
        fetch_url("https://api2.example.com"),
        fetch_url("https://api3.example.com"),
    ];
    
    return await join_all(futures);
}

// ❌ Bad: Blocking I/O (sequential)
pub proc fetch_all() -> Result<Vec<Str>, Error> {
    let mut own results: Vec<Str> = vec![];
    results.push(fetch_url_sync("https://api1.example.com")?);
    results.push(fetch_url_sync("https://api2.example.com")?);
    results.push(fetch_url_sync("https://api3.example.com")?);
    return Ok(results);
}
```

## Performance

### Use Zero-Cost Abstractions

```lppo
// Iterator chains compile to efficient loops
let own sum: Int64 = numbers
    .iter()
    .filter(|x| x > 0)
    .sum(); // As fast as manual loop!
```

### Avoid Unnecessary Allocations

```lppo
// ✅ Good: Reuse buffer
let mut own buffer: Vec<Byte> = Vec::with_capacity(1024);
loop {
    buffer.clear(); // Reuse allocation
    read_into(ref buffer)?;
    process(ref buffer);
}

// ❌ Bad: Allocate every iteration
loop {
    let own buffer: Vec<Byte> = Vec::new(); // New allocation!
    read_into(ref buffer)?;
    process(ref buffer);
}
```

### Use Appropriate Data Structures

```lppo
// For frequent lookups: HashMap O(1)
let own cache: HashMap<Str, Data> = HashMap::new();

// For sorted data: BTreeMap O(log n)
let own sorted: BTreeMap<Int64, Data> = BTreeMap::new();

// For stack operations: Vec
let mut own stack: Vec<Int64> = Vec::new();
stack.push(1);
stack.pop();
```

### Profile Before Optimizing

```lppo
// Use benchmarks to identify bottlenecks
#[bench]
pub proc bench_process_data() -> Void {
    benchmark(|| {
        process_large_dataset();
    });
}
```

## Testing

### Write Comprehensive Tests

```lppo
#[test]
pub proc test_addition() -> Void {
    assert_eq!(add(2, 3), 5);
}

#[test]
pub proc test_division() -> Void {
    let own result: Result<Int64, Str> = divide(10, 2);
    assert!(result.is_ok());
    assert_eq!(result.unwrap(), 5);
}

#[test]
pub proc test_division_by_zero() -> Void {
    let own result: Result<Int64, Str> = divide(10, 0);
    assert!(result.is_err());
}
```

### Test Edge Cases

```lppo
#[test]
pub proc test_empty_vector() -> Void {
    let own vec: Vec<Int64> = vec![];
    assert_eq!(sum(vec), 0);
}

#[test]
pub proc test_negative_numbers() -> Void {
    let own vec: Vec<Int64> = vec![-1, -2, -3];
    assert_eq!(sum(vec), -6);
}
```

### Use Property-Based Testing

```lppo
#[quickcheck]
pub proc prop_reverse_twice(vec: Vec<Int64>) -> Bool {
    let own reversed: Vec<Int64> = vec.reverse().reverse();
    return reversed == vec;
}
```

## Documentation

### Document Public APIs

```lppo
/// Calculates the factorial of a number.
/// 
/// # Arguments
/// * `n` - The number to calculate factorial for
/// 
/// # Returns
/// The factorial of n
/// 
/// # Example
/// ```lppo
/// let own result: Int64 = factorial(5);
/// assert_eq!(result, 120);
/// ```
pub proc factorial(n: Int64) -> Int64 {
    if n <= 1 {
        return 1;
    }
    return n * factorial(n - 1);
}
```

### Keep Comments Up to Date

```lppo
// ❌ Bad: Outdated comment
// Returns the sum of positive numbers
pub proc sum_all(numbers: Vec<Int64>) -> Int64 {
    return numbers.iter().sum(); // Now sums all, not just positive!
}
```

## Common Patterns

### Builder Pattern

```lppo
pub struct ConfigBuilder {
    host: Option<Str>,
    port: Option<Int64>,
    timeout: Option<Int64>,
}

impl ConfigBuilder {
    pub proc new() -> ConfigBuilder {
        return ConfigBuilder {
            host: None,
            port: None,
            timeout: None,
        };
    }
    
    pub proc host(mut self, host: Str) -> ConfigBuilder {
        self.host = Some(host);
        return self;
    }
    
    pub proc port(mut self, port: Int64) -> ConfigBuilder {
        self.port = Some(port);
        return self;
    }
    
    pub proc build(self) -> Result<Config, Str> {
        return Ok(Config {
            host: self.host.unwrap_or("localhost"),
            port: self.port.unwrap_or(8080),
            timeout: self.timeout.unwrap_or(30),
        });
    }
}
```

### Strategy Pattern

```lppo
pub trait CompressionStrategy {
    pub proc compress(data: ref Vec<Byte>) -> Vec<Byte>;
}

pub struct GzipCompression {}
impl CompressionStrategy for GzipCompression {
    pub proc compress(data: ref Vec<Byte>) -> Vec<Byte> {
        // Gzip compression
    }
}

pub struct ZipCompression {}
impl CompressionStrategy for ZipCompression {
    pub proc compress(data: ref Vec<Byte>) -> Vec<Byte> {
        // Zip compression
    }
}
```

### RAII Pattern

```lppo
pub struct FileHandle {
    path: Str,
    handle: File,
}

impl FileHandle {
    pub proc open(path: Str) -> Result<FileHandle, Error> {
        let own file: File = File::open(path)?;
        return Ok(FileHandle {
            path: path,
            handle: file,
        });
    }
}

impl Drop for FileHandle {
    pub proc drop(mut self) -> Void {
        // Automatically close file when FileHandle goes out of scope
        self.handle.close();
    }
}
```

## Summary

Follow these best practices for clean, efficient LPPO V5.1 code:

1. ✅ **Use explicit types** always
2. ✅ **Prefer Result/Option** over panics or sentinel values
3. ✅ **Use iterators** instead of manual loops
4. ✅ **Choose appropriate collections** for the use case
5. ✅ **Minimize clones** and allocations
6. ✅ **Use message passing** for concurrency when possible
7. ✅ **Keep lock scopes small** to avoid contention
8. ✅ **Write comprehensive tests** including edge cases
9. ✅ **Document public APIs** with examples
10. ✅ **Profile before optimizing** - measure don't guess

Happy coding! 🚀
